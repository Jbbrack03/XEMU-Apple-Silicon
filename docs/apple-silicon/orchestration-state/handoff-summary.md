- Key findings (durable, see `handoff.md` task #16 cycle-4 banner + `decision-log.md` cycle-4 entry + `cycle4-sampler-rt/README.md`):
  1. **Per-cell sampler state IS correct on Metal.** 32 captured stride==44 binds show exact per-cell discrimination: cell 0..6 binds report `shape_min_lvl/shape_max_lvl = 0..6` paired with `min_lod/max_lod = 0..6` and `s_levels = 1..7`. The `MTLSamplerState` cache produces a distinct sampler per cell because the `PgraphMtlSamplerDesc` memcmp key differs. Cycle-3's open question — "is the sampler per-cell correct?" — answered: yes.
  2. **`pgraph_get_texture_shape` clamps `s.levels` per cell** via `levels = MIN(levels, max_mipmap_level + 1)`. The widened-gate run histogram shows ~9-10 binds each across `s_levels = 1..7` over 64 captured lines. This is also why the cycle-2 `metal_unswizzle_dump` gate `s.levels == 7` only triggered for cell-6 binds.
  3. **The fragment-shader bordered-texture UV transform `(uv * 64 + 4) / 128` is CORRECT under the GL convention.** The GL renderer (`gl/texture.c:451-456`) and Vulkan renderer (`vk/texture.c:111`) double texture upload dimensions to 128x128 with a 4-texel border when `s.border`, satisfying the convention. The Metal renderer (`mtl/texture_pg.c::decode_face_levels` + `texture.mm::bind_slot_full`) does NOT for the non-cubemap-2D path; it uploads at the reported 64x64. `mtl_get_cubemap_face_size:598` DOES double unconditionally for `!f.linear && s.border` (byte-budget intent), but `decode_face_levels:737`'s `crop_cubemap_border = s.cubemap && s.border && !f.linear` gate excludes the non-cubemap-2D path from the actual doubling.
  4. **The XBE library tickles the bordered path accidentally.** `scripts/apple-silicon/xbe-tests/lib/xbed_texture.c::xbed_texture_bind_stage0` lines 87-93 compose the format word from `fmt = 0` without ever setting `XBED_FMT_BORDER_SOURCE_BIT`, so bit 3 stays 0 = `BORDER_SOURCE_TEXTURE` (NOT COLOR). The nxdk `samples/mesh` reference at `main.c:145` pushes `0x0001122a` whose bit 3 IS set; the library was authored to mirror that sample but missed this bit.
  5. **Root cause for the intra-mip Q0 collapse is fully explained.** Per-sub-quad UVs (0.25/0.75 × 0.25/0.75) under the bordered transform `(uv * 64 + 4) / 128` produce sample coordinates in [0.031..0.531] of the actual 64x64 texture's normalized space — landing on texels [2..34] in both axes, all of which are within the texture's Q0 quadrant (texels 0..31). The screenshot's per-mip RED tint ramp + intra-mip Q0 collapse is the geometrically-correct rendering of the bordered-UV transform against a non-bordered upload.
